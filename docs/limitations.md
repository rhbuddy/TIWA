# Current implementation status and limitations

The repository is an initial end-to-end prototype, not a completed experimental thesis. Requirements below are implemented as code paths, present as optional workflows, or still outstanding. No acceptance criterion should be reported as passed until the corresponding experiment has been run and its artifacts reviewed.

## Implemented in the current code

- Core propagation, mobility, traffic, contention/airtime, and one-second network simulation.
- Four per-AP indicators and normalized higher-is-better observations.
- Client-driven, original-interpretation TiWA, corrected TiWA, random, and TiWA + forecast policies.
- EWMA and moving-average baselines; optional ARIMA, random-forest, XGBoost, and LSTM interfaces/training entry points.
- Gymnasium environment with discrete stay/move actions, invalid-action handling, handover dwell/outage costs, fairness-aware reward, and fixed observations.
- CSV trace files, per-run KPIs, plots, paired tests, bootstrap intervals, and a configurable matrix runner.
- DQN/PPO training entry points, which require the optional ML/RL dependencies.

## Not yet demonstrated / future work

- **TiWA numerical reproduction:** a first Experiment 1 replay changed only the SRS-approved model parameter `eta` (with `n` and `tau` fixed) and was evaluated on ten distinct seeds. Aspect 1 falls within the SRS's approximate throughput tolerance and has the expected TiWA-over-client ordering. However, the assumed STA grouping/coordinates were informed by exploratory outcomes rather than independently reconstructed from Figure 3; the relative gain is larger than the paper reports, average PHY rate does not improve, occupancy is not directly comparable, and the radio/STA coordinates are approximate. This is provisional simulator evidence, not a signed-off calibration or a reproduction of the paper's physical testbed/full result set; see `paper-reproduction-results.md`.
- **Forecast acceptance:** no train/validation/test dataset or trained model is checked in; FCT-04/FCT-06 results remain to be measured.
- **RL convergence:** DQN/PPO are implemented as entry points, but no model checkpoints, five-seed curves, or policy superiority claims are included.
- **Formal 70% coverage / CI:** unit tests are supplied; coverage and static-check thresholds have not yet been measured in CI.
- **Full requirement semantics:** some behaviors are simplified in this version. In particular, scenario sampling is at the configured scenario level (not a randomized topology/traffic generator), video traffic is a lightweight bounded AR(1) modulation, no explicit TCP/UDP packet model exists, and channel assignment is heuristic.
- **Statistical event-window forecasting:** the evaluator now supports all-sample/event-window MAE/RMSE/MAPE and paired per-run Wilcoxon tests with Holm correction and bootstrap intervals. No representative held-out SRS forecast dataset has been generated or evaluated yet.
- **Mininet-WiFi/ns-3 validation:** a Mininet-WiFi backend now builds a static AP/STA topology, samples `iw` telemetry, runs the policy loop, and writes traces. The sandbox lacks Mininet-WiFi, `iw`, and wireless namespaces, so no emulator run has been completed; AC-07 remains unproven. The backend currently rejects mobility and flash-crowd scenarios.
- **Physical controller/deployment:** the Mininet backend is emulator-only. There is still no vendor-specific REST/socket integration with a production SDN controller or physical AP, no authentication/deployment hardening, and no real-client handover test.
- **Possible implementation follow-ups:** dwell-time enforcement is in the simulator/controller action path; automatic reassociation after complete link loss is modeled but not intended as a faithful client driver; the AP-to-AP collision model assumes symmetric carrier sensing.

## Reporting rule

Use only the numbers generated by a reproducible run in `results/`, keep its resolved config and seed with it, and state whether a result comes from this simulator or an emulator. Negative, inconclusive, and failed acceptance results should be reported rather than suppressed.
